# CryptoSharia Business Brainstorm

## When to use

Use this skill when the user asks for business strategy, product ideas, roadmap options, or market experiments.

## Source of truth

- `.agents/rules/cryptosharia-context.md`
- `.agents/rules/architecture.md`

## Local supplements

- `rules/idea-quality-bar.md`
- `references/experiment-brief-template.md`

## Brainstorming principles

- Prioritize trust, educational impact, and user safety over hype.
- Ground ideas in existing ecosystem platforms and API capabilities.
- Keep Sharia terminology careful and avoid over-claiming certainty.
- Avoid language that implies guaranteed financial outcomes.

## Workflow

1. Clarify objective and target persona
   - Example: beginner members, internal admins, or content operators

2. State assumptions explicitly
   - Mark unknowns and constraints before proposing solutions

3. Generate structured options
   - For each option include: user value, implementation outline, risks, and API impact

4. Recommend low-risk experiments first
   - Propose MVP test design, success metrics, and decision gates

5. Provide a phased execution path
   - Phase 1 quick wins, Phase 2 expansion, Phase 3 scale-up

## Output format

- Objective and persona
- Assumptions
- 3-5 options with trade-offs
- Recommended experiment plan
- API and operational implications

## Done definition

- Every option passes the local idea quality bar
- Recommendation includes measurable experiment criteria
- Output avoids speculative or guaranteed-return framing
